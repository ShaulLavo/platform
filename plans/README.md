## Findings considered and rejected

Recorded so the next audit doesn't re-litigate them:

- **PERF: "double/triple `normalizeWorkspaceLayout` calls" (editor-surface-layout.ts, workspace-cache.ts)** — rejected. `markNormalizedLayout` (`packages/tiling/src/utils/layout-normalize.ts:219`) caches on the _returned_ layout object and `normalizeWorkspaceLayout:49` early-returns on a cache hit, so repeat calls on an already-normalized layout are WeakMap lookups, not re-normalization.
- **PERF: `Array.includes` scans in `layout-normalize.ts` (e.g. line 514 pinned-surface filter)** — real pattern, negligible cost: the arrays are per-window surface/pin lists (single digits typically). Not worth doing without a profile showing otherwise.
- **DEBT: "dead proof folders" (`features/dnd-proof`, `shell-proof`, `tiling-proof`)** — rejected as dead code. They are imported by `apps/web/src/components/app-content.tsx`, documented as deliberate temporary proofs in `docs/tiling-surface-manager/backlog.md`, and the backlog names their tests as the regression coverage for recipe semantics. Their retirement is gated on the documented production cutover, which is direction work, not cleanup.
- **CORRECTNESS: "TOCTOU in tree query updater" (`use-workspace-events.ts:526-532`)** — rejected. The `if (!current) return current` guard _inside_ the `setQueryData` updater is the correct TanStack Query pattern (the updater receives the latest value).
- **CORRECTNESS: stale dirty-set race in `applyOpenFileOperations` (`use-workspace-events.ts:~665-700`)** — plausible narrow race (dirty set captured at batch start, file fetched after awaits, force-replace decided on stale data; partially mitigated by the `wasDirty` check + overwrite notification). Not separately planned: `PLAN.md` weeks 4–5 (FileSyncService, explicit file states, no timing-dependent correctness) is the decided remediation and supersedes a tactical patch.
- **SECURITY** — audit came back clean at standard depth: origin allowlist + auth guard enforced (and covered by `apps/server/src/tests/app.test.ts` auth suite), path containment checks before fs ops, array-based git spawns, no committed secrets (`.env` gitignored, never committed).
- **DEPS: `vite: npm:rolldown-vite@7.1.12` alias and `preact@11.0.0-beta.0`** — deliberate technology choices, not drift. Worth a one-line comment in `package.json` someday; not a plan.
- **DEBT: split `surface-registry.ts` (769 lines) into per-type descriptor modules** — speculative refactor, MED confidence, no current pain evidenced. Revisit if the agent-surfaces follow-up plan (which adds surface types) makes it concrete.
- **TEST: `packages/ui` (0 test files) and `packages/tree` (2 test files)** — real gaps, lower leverage than the git mutation paths; reconsider after 001/002 land. `apps/server/src/terminal` has one solid service test; deepening it is deferred for the same reason.
