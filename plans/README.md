## The third pass in one paragraph

This codebase does not have a quality problem — it has a **redundancy** problem.
Discipline is unusually high (0.23% duplication, 16 TODOs in 222K lines, exactly
one file violating the nesting rule, argv-only subprocess invocation with byte
budgets and deadlines, no committed secrets, comment density that explains
_rejected_ alternatives). What is wrong is almost entirely one shape: **the same
truth is written down two-to-five times by hand, and nothing checks the copies
against each other.** Nine independent auditors found that under nine different
names. Explicitly healthy and needing no work: `git/service.ts` (1,264 lines but
coherent), the settings registry's scope rule, focus-visible coverage,
popover/menu motion, `packages/contracts/src/settings/`.

## The six cross-cutting themes

Every finding above is an instance of one of these. Fixing the theme is worth
more than fixing the instances.

**T1 — Parallel hand-maintained representations of one truth** _(6 areas, ~12
findings — the dominant theme)._ The event log is folded twice by hand (1,238 +
625 lines, policed by a 551-line convergence test). The event catalog is written
three times. Session status is modelled four ways by eight lossy mappers that
_actively contradict_ each other — `waiting` means "running" to the UI,
"inactive" to session reuse, and "never reclaim" to the reaper. One chat thread
is five parallel records; one document is three representations; `entryFromStat`
exists character-for-character twice. In every case the copies are unenforced:
adding a field compiles, ships, and drifts. **One rule closes all of them: a
second representation must be _derived_, never _maintained_.**

**T2 — Typed contracts that stop being typed exactly where the consumer needs
them** _(3 areas)._ `SettingWidget` is an 11-member string union with no relation
to the schema, so `{schema: v.boolean(), widget: 'font'}` typechecks and the
settings page pays with eight casts including `(next: never) => void`.
`orchestration-ws.ts:247` is `data: v.unknown()`, so `dispatchCommand`'s result
shape is written twice and agrees by coincidence. `runtimePayload` is
`unknown | null`, so the value deciding whether a live child process is reused is
validated by five hand-written sniffers across three files.

**T3 — No shared home for a 10-line utility → N copies** _(4 areas)._ Four WS
context adapters, six `basename`s with four different behaviours, four
`omitKey`s, seven dispatch-with-telemetry envelopes in three incompatible
dialects, six `elapsedMs` helpers, seven empty-state treatments, ten
`hover:bg-*` values. Note the asymmetry: `lib/` has a real high-fan-in core
(`client` 65 importers, `file-system-types` 60) but no _membership rule_, so it
simultaneously hosts single-consumer feature modules and fails to attract the
primitives features actually need.

**T4 — Exported-but-unreachable surface** _(all package areas)._ Contracts
barrel: 43% of 467 names have zero external reference. `packages/ui`: 28% of
lines plus two locked dependencies (`ai`, `embla-carousel-react`) for code nobody
runs. `packages/tree`: 16%, exported through 8 wildcard patterns including
`internal/*`. Plus the provider SPI's dead members and a fully-built, unwired
keybindings editor. **Net ~4,400 deletable lines** — knip's 111 symbols are a
_subset_.

**T5 — Holes in the verification baseline** _(3 areas + root)._ `bun --bun
vitest run` in `apps/server` opens, migrates, and WAL-locks the developer's real
`~/.platform/fs-metadata.sqlite`. `packages/ui` has no `test` script, so root
`verify` proves nothing about it. `scripts/` — 520 LOC that starts the dev server
and produces production builds — is in no workspace and is never typechecked.
`packages/tree`'s 20K lines have 9 test cases and zero over the path store.
**Every risky item is gated on this.**

**T6 — Right gate, wrong data structure behind it** _(2 areas)._ A correct
predicate guards an operation that then does full-collection work: `--sort path`
makes ripgrep single-threaded to produce an ordering the client re-sorts two
layers later; the pending-request query has no kind predicate although the plan
query directly above it does; `WorkspaceIndex` does ~4 full map traversals plus N
cloned objects per filesystem event and the caller discards the clone.

**T7 — Design system stops at the token definition.** The oklch status ramp is
carefully tuned and then bypassed by sonner's `richColors` on the loudest surface
in the app; the diagnostics panel — whose entire job is severity — renders all
four counts in `text-foreground`; `Skeleton` has zero consumers while seven
features hand-roll empty states.

**Process observation.** Three surviving findings were already written down in
this repo's own docs (`environments-and-remote-plan.md:394` calls session-token
mode dead code; `settings-registry-inventory.md:173` independently diagnoses the
LSP `ty` module-load latch; `settings-architecture-plan.md:328` specifies the
raw-write route). **The docs record debt accurately and nothing burns it down.**
Whatever comes out of this audit needs a closing mechanism, not another
document — which is what this status table is for.

## Findings considered and rejected

Recorded so future audits don't re-litigate them.

### Reported during execution, investigated and rejected

- **"`flattenEmptyDirectories` defaults disagree between `path-store/options.ts:6`
  (`!== false`, on) and `path-store/store.ts:99` (`=== true`, off)"** — reported by
  the plan-014 executor, which correctly declined to touch production code and
  flagged it instead. **Investigated and rejected: there is no behavioral
  divergence.** `store.ts:99` reads `state.snapshot.options`, which is typed
  `ResolvedPathStoreOptions` (`internal-types.ts:104-107`) where
  `flattenEmptyDirectories` is a strict `boolean`. The default is applied exactly
  once, in `resolvePathStoreOptions`. Against an already-strict boolean,
  `=== true`, `!== true`, and a bare read are all equivalent — which is why all
  five read sites (`store.ts:99`, `static-store.ts:374`, `flatten.ts:13`,
  `projection.ts:662,764`) behave identically today.
  The residue is style, not correctness: three spellings for one boolean. It
  becomes a real bug only if someone changes `snapshot.options` to carry raw
  user options, at which point `store.ts:99` would silently flip the default.
  Worth a one-line comment on the type, not a plan.

### Third pass (2026-08-16)

- **`noOpBinding` swallows nine VS Code default keys** — rejected, and it was the
  only finding of 58 that adversarial verification killed outright. Every one is
  a browser-owned chord (Control+Tab, Mod+W, Mod+1/2/3, F12…). The
  `TODO(electron)` at `default-bindings.ts:146` states the rule, and two tests in
  `keymap/tests/keymap.test.ts` (lines 526, 583) assert the no-ops explicitly.
  Implementing the "fix" would fail both tests. By design.
- **Content-index rg exclude-glob layer** — a benchmark question, not a win.
  Deleting the globs trades a per-query index scan for per-file open-and-read on
  every known-binary file, and the scan exits early at 512 globs, so the two
  failure modes are mutually exclusive. Do not touch without a measurement.
- **`BoundedTtlCache` full-map sweep** — the 10k–20k figure is the capacity
  ceiling; the live map is keyed per (thread, turn) with a 2h TTL and holds tens
  of entries. Asymptotically wrong, practically free.
- **Minimap `transition-[width,height]`** — the `nav` is an absolutely-positioned
  sibling of the scroll container, not inside it; two 8px spans transition, only
  on active-turn change. Wrong idiom, zero measured cost.
- **Four WS context adapters → one helper** — the load-bearing claim ("terminal
  and lsp already disagree") was refuted; they are behaviourally identical, only
  spelled differently. Do it opportunistically, never as its own PR.
- **`packages/tree` entry-point restructure** — the "tree is the outlier" premise
  is false; `packages/ui` uses the same wildcard scheme and `AGENTS.md` permits
  rather than requires entry barrels. Only the deletions survive (folded into
  item 9).
- **Making `useFileTree` options reactive** — the constructor-only contract is
  _documented at the top of the hook_, not silent. Revisit only when a real
  stale-callback bug appears.
- **"Delete `ChatSidePanel`, it's a competing host"** — refuted as framed. It is
  one tab of the workbench sidebar (`sidebar-panel.tsx:130`), a deliberately
  narrow companion beside the editor.
- **Rewriting the chat timeline derivation to be incremental** — L effort, no
  profile, and the verifier found that _no chat component uses `React.memo`_, so
  the 108 lines of hand-rolled identity sharing currently buy nothing. Measure
  first; the likely answer is that the apparatus is **deletable**.
- **Consolidating the six `basename`s / four `omitKey`s** — four genuinely
  different behaviours (one lowercases for icon lookup, one normalises Windows
  separators, one falls back to the whole path). Swapping a call site is a silent
  behaviour change typecheck cannot catch.
- **Chasing the "third latent divergence" between the two projections** —
  speculative; no code path produces an out-of-order `updatedAt`.
- **Duplication (jscpd 0.23%), TODO/FIXME debt (16 in 222K lines), nesting
